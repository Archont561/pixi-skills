# Biome

A fast, all-in-one linter and formatter for TypeScript, JavaScript, CSS,
and JSON. Replaces both ESLint and Prettier with a single Rust-native
binary. See ADR-005 in [design-decisions](../architecture/design-decisions.md)
for why Biome was chosen.

---

## Installation

Biome is installed by **pixi from conda-forge** — NOT from npm.

```toml
# pixi.toml
[feature.docs.dependencies]
biome = ">=2.3"
```

This means:
- No `@biomejs/biome` in `package.json` devDependencies
- The `biome` binary version is pinned in `pixi.lock`
- Every developer and CI runner uses the exact same Biome version
- Bun's `node_modules` stays minimal — only Astro dependencies

> **Biome 2 (updated 2026-09-17):** Biome 2.0 ("Biotype") shipped
> mid-2025 with type-aware linting, multi-file analysis, and a **new
> config format** — run `biome migrate --write` once to upgrade an
> existing `biome.json` (see below). Biome 2.3 added full support for
> Vue/Svelte/**Astro** files: TS/JS inside `<script>` and CSS inside
> `<style>` of `.astro` components are now linted and formatted. That
> is why the floor is `>=2.3`. Latest stable is the 2.5.x line (500+
> lint rules, cross-file linting, plugin code fixes).

## Configuration

### Root config: `biome.json`

The workspace root contains the shared Biome configuration. All
projects inherit from this file.

```jsonc
{
  "$schema": "https://biomejs.dev/schemas/2.5/schema.json",
  "assist": {
    "actions": { "source": { "organizeImports": "on" } }
  },
  "formatter": {
    "indentStyle": "space",
    "indentWidth": 2,
    "lineWidth": 100
  },
  "linter": {
    "enabled": true,
    "rules": {
      "recommended": true
    }
  },
  "javascript": {
    "formatter": {
      "quoteStyle": "single",
      "trailingCommas": "all"
    }
  },
  "json": {
    "formatter": {
      "trailingCommas": "none"
    }
  },
  "files": {
    "ignore": [
      "dist/",
      ".pixi/",
      "node_modules/",
      "*.gen.ts",
      "*.gen.mjs"
    ]
  }
}
```

### Docs app override: `apps/pixi-skills-docs/biome.json`

The docs app extends the root config and adds project-specific rules.

```jsonc
{
  "extends": ["../../biome.json"],
  "linter": {
    "rules": {
      "suspicious": {
        "noConsole": "warn"
      },
      "complexity": {
        "noForEach": "off"
      }
    }
  },
  "files": {
    "ignore": [
      "src/content/docs/cli/"
    ]
  }
}
```

**Note**: the `src/content/docs/cli/` directory is ignored because
those `.mdx` files are auto-generated by xtask. Biome should not
lint or format generated code.

### Monorepo Config Inheritance (Biome v2+)

Biome v2 introduced first-class monorepo support. The `extends`
field supports:
- Relative paths: `"extends": ["../../biome.json"]`
- The `"//"` microsyntax: `"extends": ["//"]` (resolves to workspace root)

We use relative paths for explicitness.

## What Biome Covers

### Formatter (replaces Prettier)

| Language | File extensions | Notes |
|---|---|---|
| JavaScript | `.js`, `.mjs`, `.cjs` | Full support |
| TypeScript | `.ts`, `.mts`, `.cts` | Full support |
| JSX/TSX | `.jsx`, `.tsx` | Full support |
| JSON | `.json`, `.jsonc` | Full support |
| CSS | `.css` | Full support |
| Astro | `.astro` | Script/style blocks only (not template HTML) |

### Linter (replaces ESLint)

Biome ships 500+ lint rules organized by category:

| Category | Examples |
|---|---|
| `correctness` | No unreachable code, no unused variables |
| `suspicious` | No console logs, no duplicate keys |
| `style` | Consistent type assertions, no negation else |
| `complexity` | No excessive nesting, simplified expressions |
| `security` | No dangerouslySetInnerHTML |
| `a11y` | Alt text on images, valid ARIA attributes |
| `nursery` | Experimental rules (opt-in) |

### Import organizer

Biome organizes and sorts imports automatically:
- Groups: built-ins → external → internal → relative
- Alphabetical within groups
- Removes unused imports

## pixi Task Integration

Biome is invoked via pixi tasks, not via package.json scripts:

```toml
# pixi.toml
[feature.docs.tasks]
fmt-ts       = { cmd = "biome format --write .", cwd = "apps/pixi-skills-docs" }
lint-ts      = { cmd = "biome check .",           cwd = "apps/pixi-skills-docs" }
fmt-check-ts = { cmd = "biome check .",           cwd = "apps/pixi-skills-docs" }
```

### Command Reference

| Command | Purpose | Modifies files? |
|---|---|---|
| `biome format --write .` | Format all supported files in place | ✅ Yes |
| `biome check .` | Lint + format check (no modifications) | ❌ No |
| `biome check --write .` | Lint + auto-fix + format in place | ✅ Yes |
| `biome lint .` | Lint only (no format check) | ❌ No |

### Composite Tasks

```toml
# pixi.toml (feature: all)
fmt-all       = { depends-on = ["fmt", "fmt-ts"] }        # rustfmt + taplo + biome
fmt-check-all = { depends-on = ["fmt-check", "fmt-check-ts"] }
lint-all      = { depends-on = ["lint", "lint-ts"] }       # clippy + taplo + deny + biome
```

## Editor Integration

### VS Code / Cursor

Install the Biome VS Code extension (`biomejs.biome`). Configure it
to use the pixi-managed binary:

```jsonc
// .vscode/settings.json
{
  "biome.lspBin": ".pixi/envs/docs/bin/biome",
  "editor.defaultFormatter": "biomejs.biome",
  "[javascript]": { "editor.defaultFormatter": "biomejs.biome" },
  "[typescript]": { "editor.defaultFormatter": "biomejs.biome" },
  "[json]": { "editor.defaultFormatter": "biomejs.biome" },
  "[css]": { "editor.defaultFormatter": "biomejs.biome" }
}
```

This ensures the editor uses the same Biome version as CI.

### Zed

Zed has built-in Biome support. Configure the binary path in
`.zed/settings.json`:

```jsonc
{
  "lsp": {
    "biome": {
      "binary": { "path": ".pixi/envs/docs/bin/biome" }
    }
  }
}
```

## Astro File Handling

Biome supports `.astro` files with limitations:

- **`<script>` blocks**: fully linted and formatted (TypeScript)
- **`<style>` blocks**: fully linted and formatted (CSS)
- **Template HTML**: NOT handled by Biome — Astro's own formatter
  (`astro check`) handles template formatting

This is acceptable because:
1. Most logic lives in `<script>` blocks (fully covered)
2. Template HTML is simple in Starlight docs (mostly markdown)
3. `astro check` catches template-level issues

## Common Issues and Solutions

### Issue: Biome conflicts with Astro's generated types
**Solution**: Add `*.gen.ts` and `*.gen.mjs` to `files.ignore`.
Astro generates `env.d.ts` and content collection types that Biome
should not touch.

### Issue: Biome formats JSON differently than package.json expects
**Solution**: JSON formatting is consistent — `trailingCommas: "none"`
for JSON (standard JSON doesn't allow trailing commas). Set explicitly
in root `biome.json`.

### Issue: Import organization breaks Astro component imports
**Solution**: Biome's import organizer respects side-effect imports.
Astro's `---` frontmatter is treated as a script block, and imports
within it are organized normally. If an import has side effects, mark
it with a `// biome-ignore` comment.

## Migration Notes (From ESLint + Prettier)

If a contributor is used to ESLint/Prettier:

| ESLint/Prettier | Biome equivalent |
|---|---|
| `npx eslint .` | `biome lint .` |
| `npx prettier --check .` | `biome format .` (dry-run) |
| `npx prettier --write .` | `biome format --write .` |
| `npx eslint --fix .` | `biome check --write .` |
| `.eslintrc.json` | `biome.json` → `linter.rules` |
| `.prettierrc` | `biome.json` → `formatter` |
| `.eslintignore` / `.prettierignore` | `biome.json` → `files.ignore` |
