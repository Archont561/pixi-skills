# Docs App — Context

## What This Section Covers

The `apps/pixi-skills-docs/` directory contains a documentation website
built with Astro and the Starlight theme. It is the public-facing
documentation for the pixi-skills project — installation guides, CLI
reference, concept explanations, and contributor docs.

## Why Astro Starlight

Starlight was chosen because it provides:
- **Zero-config batteries**: sidebar, table of contents, search
  (Pagefind), dark mode, i18n, SEO, and accessible typography
  ship out of the box.
- **MDX content authoring**: docs are written in Markdown/MDX in
  `src/content/docs/`. Each file becomes a page. No routing config.
- **Autogenerated sidebar**: `autogenerate: { directory: 'cli' }`
  means adding a new CLI subcommand page requires zero sidebar config.
- **Static output**: the built site is fully static — fast, cheap to
  host, simple to deploy, no server runtime.

## Why Bun (not Node, not pnpm)

- Bun is available on conda-forge, so pixi provisions it alongside Rust.
  No system-level bun install needed.
- `bun install` and `bun run` are faster than npm/pnpm equivalents.
- `bun create astro --template starlight` scaffolds the project.
- The docs app is the only JS workload in the repo — a single bun.lock
  in `apps/pixi-skills-docs/` is sufficient. No need for pnpm workspaces
  or npm workspaces.

## The Codegen → Build Pipeline

The docs site consumes generated artifacts from the Rust side:

```
cargo xtask cli-docs
    → writes .mdx files to apps/pixi-skills-docs/src/content/docs/cli/
    → one file per subcommand (find.mdx, add.mdx, remove.mdx, etc.)

cargo xtask schema
    → writes skills-schema.json to apps/pixi-skills-docs/public/

bun run build (astro build)
    → reads the generated .mdx files + static schema
    → outputs dist/ (static HTML)
```

The pixi task `docs-build` orchestrates this:
```
pixi run -e all docs-build
    depends-on: [cli-docs, schema, docs-build-raw]
```

## Key Constraints

1. **No Rust compilation required for docs-only work.** Generated .mdx
   files are checked into git. A contributor editing prose docs can run
   `pixi run -e docs docs-dev` without installing Rust.

2. **Biome runs from conda-forge, not from node_modules.** The
   `@biomejs/biome` npm package is NOT in devDependencies. Biome is
   installed by pixi and invoked via pixi tasks. This keeps the JS
   dependency tree minimal.

3. **The docs site must build offline.** All search indexing (Pagefind)
   happens at build time. No external API calls during `astro build`.
   This supports airgapped/enterprise environments.

## Deployment

```
GitHub Actions → pixi run -e all docs-build → dist/
                                               ↓
                              GitHub Pages / Cloudflare Pages / Vercel
```

The entire build happens inside a pixi environment. CI uses
`prefix-dev/setup-pixi` to install pixi, which installs Rust + bun +
biome from conda-forge. One action, one command, fully reproducible.
