## Section Details

### Section 1: Getting Started

**Goal**: Get a user from zero to a working pixi-skills setup in
under 5 minutes.

| Page | Content | Audience |
|---|---|---|
| `installation.mdx` | Install pixi-skills via `pixi global install`, cargo install, or conda-forge. Prerequisites (pixi itself). | New users |
| `quickstart.mdx` | End-to-end example: `pixi skills add`, see the skill in your agent. 2-minute path. | New users |
| `first-skill.mdx` | Create a simple SKILL.md, test it locally, then add it to a project. | Skill authors |

**Design**: minimal prose, heavy on code blocks. The user should be
copying commands, not reading paragraphs.

### Section 2: Concepts

**Goal**: Build the mental model. After reading this section, a user
understands what pixi-skills does and why it exists.

| Page | Content |
|---|---|
| `what-are-skills.mdx` | What skills are, why AI agents need them, the analogy to man pages / README files. Historical context (skills.sh, manual copy-paste). |
| `providers.mdx` | The provider model: GitHub, conda, prefix.dev, PyPI. What each provides. How the `SkillRegistry` trait enables extensibility. |
| `lockfile.mdx` | Why lockfiles matter for skills (reproducibility, integrity, collaboration). How `skills-lock.toml` works. Comparison with Cargo.lock / pixi.lock / package-lock.json. |
| `agent-targets.mdx` | How pixi-skills detects agents (Claude, Cursor, Codex, etc.) and installs skills into their config directories. Auto-detection vs. manual config. |

**Design**: concept-oriented, with diagrams and analogies. Not task-
oriented — no "do this" instructions. Links to guides for hands-on
follow-up.

### Section 3: Guides

**Goal**: Task-oriented walkthroughs for specific workflows.

| Page | Content |
|---|---|
| `creating-a-skill.mdx` | Step-by-step: write SKILL.md, add TOML frontmatter, test locally, publish. |
| `publishing-conda.mdx` | Create a `skill-*` conda package using rattler-build, publish to conda-forge or a private channel. |
| `publishing-github.mdx` | Publish a skill as a GitHub repo. Naming conventions, tagging versions, SKILL.md placement. |
| `private-channels.mdx` | Set up a private conda channel on prefix.dev or Artifactory. Configure auth. Install skills from private channels. |
| `migrating-from-skills-sh.mdx` | For existing skills.sh users: what changes, what stays the same. Migration steps: `npx skills` → `pixi skills`. |

**Design**: numbered steps, expected output after each step, "what
went wrong?" troubleshooting sections at the end.

### Section 4: CLI Reference

**Goal**: Comprehensive reference for every CLI subcommand.

| Page | Source | Content |
|---|---|---|
| `overview.mdx` | Hand-written | How pixi-skills works as a pixi extension, global options (`--verbose`, `--quiet`, `--json`), general usage patterns. |
| `find.mdx` | Generated by xtask | Usage, arguments, options, examples. |
| `add.mdx` | Generated by xtask | Usage, arguments, options, examples. |
| `remove.mdx` | Generated by xtask | Usage, arguments, options, examples. |
| `list.mdx` | Generated by xtask | Usage, arguments, options, examples. |
| `update.mdx` | Generated by xtask | Usage, arguments, options, examples. |
| `lock.mdx` | Generated by xtask | Usage, arguments, options, examples. |
| `doctor.mdx` | Generated by xtask | Usage, arguments, options, examples. |

**Design**: auto-generated pages follow a strict template: synopsis,
description, arguments, options, examples, see also. The `overview.mdx`
page is the only hand-written page in this section.

**Important**: generated files contain a comment header:
```
{/* AUTO-GENERATED by `cargo xtask cli-docs`. Do not edit.
    Modify crates/pixi-skills/src/cli.rs instead. */}
```

### Section 5: Architecture

**Goal**: Help contributors understand the codebase.

| Page | Content |
|---|---|
| `crate-overview.mdx` | Visual crate dependency graph, what each crate does, how they relate. Entry point for code contributors. |
| `provider-trait.mdx` | The `SkillRegistry` trait in detail: methods, error handling, async considerations. How to implement a new provider. |
| `extending.mdx` | How to add a new provider crate: scaffold, implement trait, register in CLI, test. Step-by-step contributor guide. |

**Design**: aimed at Rust developers. Includes code snippets from the
actual source (referenced, not copied — links to source files).

### Section 6: Reference

**Goal**: Spec-level documentation for file formats and configuration.

| Page | Content |
|---|---|
| `skills-toml.mdx` | Complete specification for `skills.toml`. Every field, its type, default value, and example. JSON Schema link. |
| `skills-lock-toml.mdx` | Complete specification for `skills-lock.toml`. File format, fields, integrity model. |
| `skill-md-format.mdx` | The SKILL.md file format: TOML frontmatter schema, markdown body conventions, examples for each agent. |
| `environment-variables.mdx` | All environment variables pixi-skills reads: `GITHUB_TOKEN`, `PREFIX_DEV_TOKEN`, `PIXI_SKILLS_CACHE_DIR`, etc. |

**Design**: table-heavy, exhaustive. Every field is documented. This
is the "RFC" of pixi-skills.

## Page Ordering (Sidebar)

Starlight orders pages within an autogenerated sidebar group by:
1. The `sidebar.order` frontmatter field (lower = earlier)
2. Alphabetical by filename (fallback)

We use `sidebar.order` in frontmatter to control ordering:

```mdx
---
title: Installation
sidebar:
  order: 1
---
```

### Recommended ordering

| Section | Page order |
|---|---|

## Content Authoring Conventions

### Frontmatter

Every page must have:
```mdx
---
title: "Page Title"
description: "One-line description for SEO and link previews"
sidebar:
  order: N
---
```

### Headings

- `h1` (`#`): never used in content — Starlight generates it from
  `title` frontmatter
- `h2` (`##`): major sections within a page
- `h3` (`###`): subsections — included in table of contents
- `h4` (`####`): sub-subsections — NOT in table of contents

### Code Blocks

Use Astro Expressive Code features:

```mdx
```bash title="Install pixi-skills" {2}
# Install pixi first (if not already installed)
curl -fsSL https://pixi.sh/install.sh | bash
# Then install pixi-skills
pixi global install pixi-skills
```​
```

- `title="..."`: shows a title bar on the code block
- `{2}`: highlights line 2
- Language tag: enables syntax highlighting

### Admonitions

Starlight supports admonitions via `:::` syntax:

```mdx
:::note
This feature requires pixi-skills v0.2.0 or later.
:::

:::caution
Running `pixi skills update` without a lockfile will fetch the
latest version of every skill.
:::

:::danger
Never share your `PREFIX_DEV_TOKEN` in public repositories.
:::
```

### Cross-References

Link to other pages using relative paths:

```mdx
See the [lockfile concept](/concepts/lockfile/) for details.
See the [`add` command](/cli/add/) reference.
```
