monorepo, explaining the purpose of every directory and significant
file.

## Directory Roles

### `crates/` — The Rust workspace

All Rust code lives here. The directory contains library crates and
binary crates but no build automation (that lives in `xtask/`).

**Convention**: every crate in `crates/` is a workspace member declared
in the root `Cargo.toml`:
```toml
[workspace]
members = ["crates/*"]
```

The `xtask/` directory is NOT inside `crates/` because it is not a
publishable workspace member — it is tooling. Keeping it at the top
level makes this distinction visible in the directory tree.

### `apps/` — Non-Rust applications

Currently contains only `pixi-skills-docs/`. The `apps/` prefix signals
"these are standalone applications with their own dependency management"
(bun.lock, package.json). If future apps are added (e.g., a web-based
skill registry browser), they go here.

**Convention**: each app in `apps/` manages its own JS dependencies via
`package.json` + `bun.lock`. Pixi provisions the runtime (bun) but does
not manage JS packages — that's bun's job.

### `xtask/` — Build automation

A standalone Rust crate at the workspace root (not inside `crates/`).
It has `publish = false` and exists solely for developer tooling. It
depends on workspace crates (e.g., `pixi-skills` for clap introspection)
but is never depended upon by them.

**Convention**: `xtask` is accessed via `cargo xtask <subcommand>`,
enabled by the alias in `.cargo/config.toml`. In practice, developers
use `pixi run` which delegates to `cargo xtask`.

### `completions/` — Generated artifacts

Shell completion scripts generated by `cargo xtask completions`. These
are checked into git so users can source them without building from
source. They are regenerated as part of the release process.

### `.knowledge/` — Project knowledge base

Markdown files with YAML frontmatter, organized into sections. Read by
AI coding agents and human contributors. Not deployed anywhere — purely
a repo-local resource.

## Config File Map (Quick Reference)

| File | Tool | Scope |
|---|---|---|
| `pixi.toml` | pixi | Environments, deps, tasks |
| `Cargo.toml` (root) | cargo | Workspace members, shared deps |
| `.cargo/config.toml` | cargo | Aliases (`xtask`) |
| `biome.json` (root) | biome | TS/JS/CSS lint+format rules |
| `biome.json` (docs) | biome | Docs-specific overrides |
| `deny.toml` | cargo-deny | License + advisory policy |
| `taplo.toml` | taplo | TOML formatting rules |
| `.convco` | convco | Commit types + scopes |
| `rustfmt.toml` | rustfmt | Rust formatting rules |
| `.config/nextest.toml` | cargo-nextest | Test profiles, timeouts |
| `astro.config.mjs` | astro/starlight | Docs site config + sidebar |
| `tsconfig.json` (docs) | typescript | TS config for Astro |
| `package.json` (docs) | bun | JS deps + scripts |

See [conventions/config-files](../conventions/config-files.md) for
full details on each config file's contents and schema.

## What Does NOT Live in This Repo

| Concern | Where it lives | Why |
|---|---|---|
| Published skill packages | conda-forge / prefix.dev channels | Skills are consumed, not authored here |
| Example skills | Separate `pixi-skills-registry` repo (future) | Keeps the tool repo focused |
| VS Code extension | Separate repo (future) | Different release cycle, different audience |
| Benchmarks | `crates/*/benches/` (if needed) | Not yet needed at MVP stage |
